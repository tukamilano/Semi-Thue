# Semi-Thue

固定長で, 文字列の書き換え規則を用いて, ある文字列から別の文字列へと変換する問題を考える.

Semi-Thue系より一般的に https://cdn.aaai.org/AAAI/2007/AAAI07-181.pdf の論文をちゃんと読んでPAC達成時やadmissibleの時の評価をできるようにする(並列化やオーバーラップ抜きでsemi-thue系の特性とかを使わずに)

beam search -> 到達可能性を扱う
A* -> 最短変換を扱う
- 文字列置換がk=1文字の場合, 2文字以上の場合とかを考えていく

- PAC達成したときにおける探索(beam searchの到達確率やA*で最短変換を発見するのに必要なコスト)の成功確率を調べる
  
  - A*は準一貫ポテンシャルでのヒューリスティックスを使う(並列化とかも考慮できる?)
  
- ハミング距離やn-gram線形回帰(安全にadmissibleを達成するため)を使うときにどうなるかを調べる
  - beam searchの到達確率(並列化とかを考慮する)
    - 分岐度とか
    - 正解のパスが漏れ落ちる確率をチェック
  - A*で最短変換を発見するのに必要なコスト(admissibleが保証できそう)
    - このadmissibleのupper bound以上に並列化とかオーバーラップとかを考慮したらより良いupper boundが取れるのでは?
  - 線形関数では準一貫ポテンシャルを作れないことを例示する

- cnnには例えばハミング距離やn-gram線形回帰を使ったbeam searchよりも良い結果を得られる保証がある(シミュレーションできるという点で)

- 今回のSemi-Thue系の特徴について
  - 積み重ね
    - 積み重ね方を調べる <- 並列化のもとになるもの(そういう意味では全く違うパスからの解は存在しないことを仮定してる)
    - 並列化に関して極限をとってエントロピーを考える(ハミング距離で) <- 全ての文字列に到達可能であるということを仮定する(等重率の原理を仮定)
  - 途中で全て変換できなくなる確率とか
    - 打てるところが確実に1つ減るけど最大2k-1個打つ可能性が生まれるところが増える
    - この部分の解析にオーバーラップが使われるというわけか
    - 到達可能性とかのチェックをする
